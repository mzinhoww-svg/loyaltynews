# ADR-004 — Os 64 perfis como contratos executados sob demanda

Estado: **Proposta** (R0-08, preparação para aceite retroativo; não aceita). Autor: Chief Architect. Revisão: Independent QA.

**Revisa:** ADR-004 de 03 §9 (revista: 64 mantidos por D04/CP-03)  
**Achados:** F-020, F-023

## Contexto
D04 manteve os 64 perfis; CP-03 manteve a correção: contratos diferenciados e IDs sem colisão. O registro é contrato lógico, não import nativo do OpenBot (Blueprint §2).

## Decisão proposta
Cada perfil é uma configuração versionada (prompt, lista de ferramentas, esquema de saída, KPI, dica de rota) executada sob demanda por um conjunto pequeno de agentes do OpenBot. Não há 64 processos residentes. Memória de trabalho fica no PostgreSQL, por redação e por matéria, não no agente. Os perfis de redação diferem por configuração de editoria (fontes, glossário, estilo).

## Alternativas consideradas
64 agentes residentes do OpenBot com memória própria; perfis enxutos (~16, M2 B/C, rejeitados por D04).

## Consequências
Menos contexto carregado e menos custo; o mapeamento perfil → agente é parte do adaptador (R2-10/R4-04).

## Critério verificável
- Validação do registro: 64 entradas, IDs únicos, nenhum ID igual a nome de diretoria, cada perfil com `output_contract` e `allowed_tools` próprios.
- R4-04: saída fora do esquema é rejeitada (teste por perfil).
- Contagem de agentes do OpenBot de produção ≤ tamanho do conjunto definido em R2-10; nenhuma escrita de memória de trabalho fora do PostgreSQL (auditoria das ferramentas).

## Mudança protegida necessária
Não.

## Não verificado
Tamanho ideal do conjunto de agentes (medir em R4).
