# ADR-010 — Governança: arquivos, CLI, MCP local e aceite por tag do verificador

Estado: **Proposta** (R0-08, preparação para aceite retroativo; não aceita). Autor: Chief Architect. Revisão: Independent QA.

**Revisa:** ADR-010 de 03 §9 (revista: D01, D02, DP-01 rev., DP-06, DP-07)  
**Achados:** F-120, F-121, V21-07, V21-16

## Contexto
D02: aceite por tag assinada pelo verificador. DP-01 revisado: o executor usa a conta admin do proprietário. DP-06: repositório do verificador público (rulesets e ambientes no plano gratuito). DP-07: raiz neste PC. V21-16: governança falha no Windows.

## Decisão proposta
Governança em arquivos versionados + CLI + MCP local stdio (10 ferramentas de leitura e 3 de proposta). Aceite só por tag anotada assinada pela chave do verificador (`task/<id>/accepted`, `gate/<Rn>/accepted`), emitida no repositório verificador público, cujo `main` exige commits assinados pela raiz; ledger público só com metadados e hashes. O executor admin não forja aceite (a assinatura não está ao seu alcance), mas pode desligar controles do GitHub: detecção pelo job `guard`. Patch V21-16 v2 para o Windows.

## Alternativas consideradas
Aceite por PR humano (ADR original, contrário a D01); MCP remoto com banco (M9 A).

## Consequências
F-120 só fecha por mudança protegida do critério (executor admin); V21-07 enfraquecido; a raiz depende da senha do proprietário.

## Critério verificável
- R0-05: os 13 testes do MCP e os 4 de política de bytes passam (no Windows, com o patch V21-16 v2).
- R0-03/R0-06: tag de aceite criada com a chave do executor é recusada pelo leitor; commit não assinado pela raiz no `main` do verificador é rejeitado.
- O `guard` detecta mudança de ruleset, visibilidade ou colaboradores e não assina nada enquanto houver desvio.

## Mudança protegida necessária
Sim: itens 1, 7 e 8 de `mudancas-protegidas-a-ratificar.md`.

## Não verificado
Matriz remota de R0-03/R0-06; WSL.
